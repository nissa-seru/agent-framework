- A channel tune-out whose channel isn't registered any more, because its server removed the channel (as a connector does when a channel is deleted or a thread archives) or the server itself went away, can be seen and ended again. `tune_out` and `focus` mode `check` list it, marked `connected: false`, with `lastSeenLabel`, the latest label its id was seen with on any server, where there is one. `peek` shows what it holds, and `tune_out` mode `cancel` ends it and delivers its backlog. Each takes the channel's id with `serverId`, its server-qualified name, or its id alone where no registered channel answers to the id and no other such tune-out shares it. The subconscious's `cancel_tuneout` takes its id or its server-qualified name the same way. Before, `check` didn't list such a tune-out, `tune_out`'s cancel and peek answered "unknown channel", and `cancel_tuneout` reached it only with a `serverId` its schema doesn't declare. So a tune-out with no duration could hold its backlog until the channel registered again, which a deleted channel never does.
  - A name a registered channel answers to still means that channel. An id that two such tune-outs share is refused, saying how to name each alone.
  - The refusal of a cancel that names no tune-out lists every tune-out, marking those whose channel isn't connected now, where it listed connected channels only.
